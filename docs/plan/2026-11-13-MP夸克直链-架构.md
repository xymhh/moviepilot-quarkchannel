# MP 夸克直链频道 — 架构 v2（按 V3 官方开发指南对齐）

> 依据：`jxxghp/MoviePilot-Plugins/blob/main/docs/Plugin_Development.md`（V3）
> 目标：网盘分享链接以**原生 MP 资源**身份进入 MP 的 搜索 → 订阅 → 下载 → 整理 → STRM → Emby → 通知 全链路。
> 不使用 CloudSubscribeX，不引用其代码/配置/表。

## 0. 官方硬约束 → 本方案落法

| 官方条款 | 本方案落法 |
|---|---|
| 新插件放 `plugins.v3/<小写id>/__init__.py`，目录名与类名小写一致 | `plugins.v3/quarkchannel/__init__.py`，类 `QuarkChannel` |
| 元数据三处一致（`plugin_version` / `package.v3.json` / `history`） | 版本号单点写入 `version.txt`，CI 校验三处一致 |
| 只能用稳定 SDK（`app.sdk.*`）；`app.core/app.helper/app.utils` 禁止 | 全部走 `app.sdk.plugin / network / cache / config / logging / scheduler / services / database` |
| 不得在导入期起线程、连网、连库 | 模块顶层只放常量与类型；资源在 `init_plugin()` 建、`stop_service()` 释放 |
| 后台/定时任务交给宿主调度器 | 周期清理用 `get_service()`；一次性任务用 `app.sdk.scheduler.add_plugin_once_job()`；**不自建 BackgroundScheduler** |
| 自有表用 `get_database_models()` + `plugin_declarative_base()` | 三张表走该通道；PostgreSQL 下自动限定插件 schema；事务只用宿主四个装饰器 |
| 插件数据不写入源码目录 | 缓存/临时文件放 `get_data_path()`，下载落 `/downloads` 白名单目录 |
| HTTP 用 `AsyncRequestUtils`（HTTPX2），不全局改写 httpx | 所有夸克/115/pansou/hdhive 请求走 `AsyncRequestUtils`；异常捕获 `httpx2.RequestError` |
| 插件 API 路径 `/api/v1/plugin/<ID>/<path>`，默认 apikey | 页面接口 `auth: "bear"`；合成种子接口 `allow_anonymous: True` + HMAC 自校验（见 §4） |
| 第三方依赖尽量为零、不降级宿主依赖 | **零新增依赖**：bencode 自己写（约 40 行），HTTP/调度/DB 全用宿主 SDK |
| 测试放 `tests/v3/<plugin_id>/`，用宿主 venv 跑 | 单测覆盖 bencode、选题、签名、状态机；外部网络 mock |
| 发布前跑真实加载检查 5 条 | 见 §8 验收清单 |

## 1. 核心决策（不变）

| MP 约束（源码） | 方案 |
|---|---|
| 非 `magnet:` 的 enclosure 一律当 `.torrent` 解析（`application/torrent/download.py:474`），失败即放弃 | **合成种子**：插件暴露 `.torrent` 端点，把分享文件清单编码成合法 torrent |
| 剧集集数必须先读种子文件清单（`chain/download/batch.py:210`），磁力恒返回 None | 合成种子含真实文件名 → MP 集数解析/整季/拆包/分包全原生工作 |
| `DownloaderType` 仅 3 枚举（`schemas/types.py:684`） | 不改枚举；插件实现 `download`，插件 provider 先执行并短路（`runtime/extensions/module/dispatcher.py:238`） |
| `StorageSchema` 无 quark（`schemas/types.py:758`） | 不做夸克存储；统一落本地，需要网盘直读时用 MP 原生 alist/rclone |

**已核实：本方案用到的 8 个模块方法均对插件开放**（`public_to_plugins=True`）：
`search_torrents`、`download`、`list_torrents`、`torrent_files`、`downloader_info`、`start_torrents`、`stop_torrents`、`remove_torrents`。

## 3. 挂点与签名（以 `app/runtime/extensions/module/contracts.py` 为准）

```python
# get_module() 返回的方法表（名称必须与合同一致）
{
  "search_torrents": self.search_torrents,
  "download": self.download,
  "list_torrents": self.list_torrents,
  "torrent_files": self.torrent_files,
  "downloader_info": self.downloader_info,
  "start_torrents": self.start_torrents,
  "stop_torrents": self.stop_torrents,
  "remove_torrents": self.remove_torrents,
}
```

| 方法 | 合同要点 | 实现 |
|---|---|---|
| `search_torrents(site, keyword, mtype, page)` | ORDERED_LIST_MERGE，MP 以 `site={}` 调用 | 三源并发（TG/pansou/hdhive）→ `TorrentInfo` 列表；`enclosure` 指向 `/torrent` 端点 |
| `download(content, download_dir, cookie="", episodes=None, category=None, label=None, downloader=None, custom_words=None)` | FIRST_NON_EMPTY，插件短路 | 解析种子 `comment` → 分享 id → 按 `episodes` 过滤 → 直链分片下载 → `("网盘直链", hash, layout, "")` |
| `list_torrents(status, hashs, downloader, include_all_tags)` | ORDERED_LIST_MERGE | 任务表投影 `DownloaderTorrent`（progress/state/dlspeed/save_path/content_path） |
| `torrent_files(tid, downloader)` | FIRST_NON_EMPTY | 返回文件清单 + 单文件进度 |
| `start/stop_torrents(hashs, downloader)` | FIRST_NON_EMPTY | 置任务事件位，worker 响应 |
| `remove_torrents(hashs, delete_file, downloader)` | FIRST_NON_EMPTY | 删记录 + 可选删文件（限 `local_roots` 白名单） |
| `downloader_info(downloader)` | ORDERED_LIST_MERGE | 返回「网盘直链」实例，供下载器面板展示 |

## 4. 合成种子端点

声明（`get_api()`）：

```python
{
  "path": "/torrent",
  "endpoint": self.api_torrent,
  "methods": ["GET"],
  "allow_anonymous": True,          # 由插件自己做 HMAC 校验
  "summary": "按分享 id 生成合成种子",
}
```

- URL：`http://<mp_base_url>/api/v1/plugin/QuarkChannel/torrent?sid=<id>&sig=<hmac>`
- MP 侧 `TorrentHelper` 会**直接拉取**该 URL（不带任何登录态），所以必须匿名可达；安全性靠签名：
  `sig = HMAC-SHA256(secret, sid + provider)`，secret 随机生成存插件配置，可轮换；签名不匹配 → 403。
- 内容（bencode v1）：`name`=分享标题、`files[]`=真实文件名与大小、`piece length`=262144、`pieces`=全零（上限 1MB）、`comment="QUARKCHANNEL|<sid>|<provider>"`。
- `info_hash` 由内容 sha1 决定 → 同一分享恒等 hash，MP 的历史/去重/重试天然对齐。
- 缓存：内存 10 分钟（`app.sdk.cache`）+ 磁盘 1 小时（`get_data_path()`）；sid 失效返回 404。

## 5. 数据

```python
# models.py
from app.sdk.database import plugin_declarative_base
Base = plugin_declarative_base()

class QuarkTask(Base):      # hash 主键，sid/provider/share_url(加密)/title/folder_name/
    ...                     # save_path/total_size/done_size/state/error/file_list(json)/retry_count
class QuarkCache(Base):     # sid 主键，files(json)/total_size/expires_at
class QuarkStat(Base):      # provider 主键，ok/fail/last_error/avg_seconds
```
- 通过 `get_database_models()` 声明；PostgreSQL 下自动限定到插件 schema。
- 写操作只用宿主的四个事务装饰器；重复初始化要能幂等建表。
- 敏感字段（分享 URL、cookie）入库存加密值，日志只打 `sid` 前 6 位。

## 6. 并发与线程模型

- 网络：`AsyncRequestUtils`（HTTPX2），单源并发 ≤2，全局取链 QPS ≤2，退避 1s/4s/16s。
- 下载：固定 3 个 worker 的线程池（`threading.Thread` + 队列，`stop_service()` 里 join + 置停止位）；
  单文件 8–64MB 自适应分片 + Range 续传；速度 <200KB/s 持续 60s 判"慢"并记录原因。
- 周期任务（`get_service()`）：清理过期缓存（每小时）、残留清理（每日 03:40，mtime>24h 且无对应任务）、源健康度汇总。
- 一次性任务：`add_plugin_once_job()`（例如保存配置后立即刷新源状态）。
- 插件停用：`enabled=false` → `search_torrents` 返回空 → MP 自动回落到原生 BT/PT，无脏数据。

## 7. 失败与回滚

```
取链 403/风控/限速 → 重试 3 次 → 标记该候选失败（MP 原生失败记录 + 冷却）→ 换候选
分享失效 → /torrent 404 → MP 判"无法获取下载地址"并冷却 → 换候选
磁盘不足 → 立即中止 + post_message 系统通知
插件停用 → MP 把假种子交给 qb → 必然失败（安全失败，不产生脏数据）
```

幂等：同 hash 且 state ∈ {downloading, completed} → 直接返回原任务（对齐 `DOWNLOAD_TASK_ALREADY_EXISTS`）。

## 9. 风险与不做

| 风险 | 缓解 |
|---|---|
| 夸克直链风控/限速 | 3 次退避 + 慢速判定 + 换候选 + 源健康度降权 |
| 合成种子是"假"的 | 插件停用即安全失败；`comment` 前缀可识别，不会误入真实下载器 |
| 匿名端点暴露 | HMAC 签名 + 仅绑定分享 id + 服务端 24h 内只允许本机来源（`127.0.0.1`） |
| MP 升级改合同 | `system_version: ">=3.2.0"`；升级后跑 M1 回归 |

不做：改内核、加 `DownloaderType`/`StorageSchema`、夸克存储、BT 做种语义、接管 MP 的订阅/过滤/整理。
